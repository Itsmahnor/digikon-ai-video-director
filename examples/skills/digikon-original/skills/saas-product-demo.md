**When to use:** a viewer is evaluating the product and wants to see it work.

**Structure:** (1) the job to be done in one sentence; (2) the product doing that job in one continuous, real flow; (3) the result on screen; (4) one next step.

**Scene beats (60 s):** 0-5 s problem and promise; 5-45 s three actions at most, each shown on real UI with a short label; 45-55 s the outcome; 55-60 s CTA.

**Pacing:** hold each UI state long enough to read it, about 2 to 3 seconds; zoom or highlight the control being used; cursor movement should be deliberate, not fast.

**Asset needs:** screen recordings or accurate captures, logo, the brand colours, the one CTA and its URL.

**Claims:** only claims backed by the facts the user supplied; no invented statistics, prices, customer names or testimonials; flag regulated claims (health, finance, legal) for review. Show only features that exist; never mock up a screen that is not real.

**Example:** "Send an invoice in three clicks": create, add client, send, with the paid status shown last.
