# Plan text for Phases A, B and C (as received)

This is the step spec the working session was given, copied here so the plan lives with the code. It came as briefs from the coordinator session, which quoted `UPDATED_PLAN.md` and `IMPLEMENTATION_STEPS.md` (those files are not in the repo). Phases D to G were not provided; see `docs/HANDOFF.md`. Status and commit hashes are in `docs/HANDOFF.md`, not here.

Standing rules that came with every brief: one reviewable local commit per step; no pushing without asking (Digikon pushes); never loosen the two approval gates or the render gate; keep the suite green (last known baseline 1,598 passed, 6 skipped, later 1,659 and more); label anything unproven (real network, real LLM, real Postgres server).

## Phase A

**A1 Run DB for real:** `npm run db:up`, `npm run db:migrate`, run `packages/rag/src/db/pg.integration.test.ts` with `DATABASE_URL` set. Done when `db:health` is OK and the integration test passes. (If Docker is missing: say so and fall back to PGlite for tests; ask before installing anything. Exit criterion for Phase A: integration tests pass on a real DB.)

**A2 Skills tables with licences:** migration `db/migrations/0002_skills.sql`: `skill_sources(repo, url, licence, checked_on)`, `skills(id, category, funnel_stage, platform, grade, status, body, content_hash, source_id)`, `skill_embeddings`, `assets_library(kind fonts/sounds/music, file, licence, source)`. A row cannot be saved without a licence. Add skills methods to `packages/rag/src/db/store.ts` and a `SkillRecord` contract in `packages/contracts/src`. Done when a unit test proves a skill without licence is rejected.

**A3 Importer:** `npm run skills -- import <folder|repo>` in `scripts/skills.mts` + `packages/rag/src/skills.ts` (reuse `templates.ts` dedupe and `embeddings.ts`). Pipeline: read files -> licence check against the allow-list (MIT, Apache-2.0, BSD, CC0, CC-BY with attribution stored; refuse anything else and print why = step B0 licence gate) -> normalise to `SkillRecord` -> near-duplicate removal -> embed -> store. Done when importing a sample folder stores records and a repeat import changes nothing.

**A4 Retriever over the skills table:** keyword + vector with the existing filters (status, grade, aspect, platform) plus a category filter; `packages/rag/src/hybrid.ts` (`storeVectorIndex`), `scopes.ts` adds skills to the Director and Editor scopes. Existing retrieval tests must pass; a category query returns only that category.

## Phase B

**B1 (schema correction):** `category` must be the video category the plan filters on: `saas | ecommerce | general-promo | all` (all = cross-cutting). A query for saas returns saas AND all; never another specific category. A separate `topic` field holds the concept slug (video-type-playbook, hook, structure, pacing, text-captions, cta-offer, brand, claims-safety, accessibility, audio, asset-gaps, motion, visual-design, renderer, ...). A `scope` field (`director | editor | both`) says who reads a skill; migration `0003_skill_scope.sql`.

**B2 Skill content:** per-source folders under `examples/skills/`, each with `skills-source.json` (repo, URL, licence, attribution), the source's LICENSE, and `skills/*.md` in the Director format (when to use, structure, scene beats, pacing, claims warnings, example). Repo-derived skills are short condensed adaptations with source URL, licence and the copyright holder as attribution, never copies; sources: creatify-ai/video-ad-generator, sergebulaev/tiktok-skills, matt-j-penny/ai-video-marketing, EveryInc/product-launch-video, iart-ai/explainer-video-skills, kmilo93sd/agent-video-editor (MIT); heygen-com/hyperframes, Vincentwei1021/video-shotcraft, three Apache-2.0 skills of anthropics/skills (canvas-design, theme-factory, frontend-design). Exclusions: product-launch-motion's films and logos, matt-j-penny's csv and fonts, anything needing Apify/Publora/Creatify API, the proprietary anthropics docx/pdf/pptx/xlsx and brand-guidelines skills, sample outputs and assets. `remotion-dev/skills` has no LICENSE and must be refused by the gate; write original Remotion skills (source digikon-original, licence MIT) with the warning "Remotion has its own licence; check remotion.dev/license before commercial use." Originals (source digikon-original, MIT, Copyright Digikon): video-type playbooks (SaaS demo, feature launch, explainer, onboarding, testimonial; e-commerce showcase, UGC-style, unboxing, offer/sale, comparison; general promo brand story, event teaser, announcement, social ad), funnel stages, platform rules, hook patterns, problem-solution-proof-CTA, scene beats and pacing, on-screen text and captions, CTA and offer clarity, brand consistency, proof and claims safety, accessibility, audio/music/VO, asset gaps. Grade honestly (C), status draft until reviewed.

**B3 Benchmark and wiring:** (1) extend the retrieval benchmark with category queries over the skills corpus for saas, ecommerce, general-promo (include cross-cutting `all`); run BM25 baseline against hybrid; report numbers honestly including if hybrid does not beat BM25; for benchmarking only use `include_draft`, never change a skill's status. (2) Wire the Director treatment and storyboard to retrieve category skills (category filter = the project's video category + all, Director scope) and the Editor to retrieve editor/both scope skills; skills used are recorded in the run audit like citations already are (`packages/director/src/nodes.ts`). (3) `apps/console/src/server.ts`: build the DB-backed retriever when `DATABASE_URL` is set; keep the keyword retriever as fallback otherwise. (4) An explicit, documented config switch (`SKILLS_INCLUDE_DRAFT=1`, default off) so demos run without editing statuses. (5) A demo run per category with the stub model, showing citations.

**B remaining items:** (1) an off-topic floor: off-topic queries return nothing (tune on the dev split only, report on test; add the off-topic cases as tests). (2) Independent benchmark queries: a new set of about 40 per category (saas, ecommerce, general-promo, plus cross-cutting and off-topic) written without looking at skill bodies, ground truth by topic/category rules decided before running; keep the old 51 as a separate set; re-run BM25 vs hybrid and set the default to the better one on the held-out new set. (3) `video_category` field in the console intake (UI, route, Project payload): saas | ecommerce | general-promo | unset = cross-cutting only, with a test. (4) Skill review: a written checklist (licence and attribution present and matching the repo LICENSE; no verbatim long copy of sources; claims safety; no invented stats; platform numbers flagged as defaults; within the Director format); apply to all skills and promote only passing skills draft -> reviewed (never approved); keep skills whose source was only skimmed as draft; record the result per skill in a review file; say plainly that the review was done by the same agent that wrote them and needs a human spot-check; confirm retrieval shows reviewed skills with `SKILLS_INCLUDE_DRAFT` off and hides draft. (5) Re-run the full suite, update docs and `.env.example`, report numbers, counts, commit hashes and what is unproven.

## Phase C: guided intake and question module (no model provider needed)

**C1 Project kit contract:** versioned `ProjectKit`: goal, audience, platform, brand (colours, fonts, logo, tone), website, guideline file, assets, facts, and for each field `provided | skipped | missing`. Linked to `Project.brand_id` (and the new optional `video_category`). File: `packages/contracts/src/kit.ts`. Done when schema tests cover every skip and missing case.

**C2 Website reader:** fetch a page, extract colours, fonts, headings, copy and logo, with timeouts and a size limit. Failure (blocked, no JS content, offline) returns "could not read" and the wizard asks the user instead. Extracted facts are shown to the user to confirm before they count as approved brand facts (never auto-approved). Files: `packages/media/src/website.ts`, console route `POST /api/sessions/:id/website`. Security: block private/loopback/link-local addresses (SSRF), limit redirects, size and content types; test with a local fixture server, no real internet needed.

**C3 Brand guideline reader:** PDF text and colour extraction, same confirm step; an unreadable PDF falls back to asking.

**C4 Intake wizard (UI):** steps goal, audience, platform, brand, website, assets; each optional step has Skip, progress saved, a returning user can reuse the saved brand kit. Files: `apps/console/public/app.js`, `index.html`, `styles.css`, routes in `apps/console/src/app.ts`. Done when edge cases work in a browser test (Playwright was said to be available; it is not installed on this PC): no logo, no website, unreadable PDF, wrong file type, huge file, user goes back and changes an answer.

**C5 Completeness check:** deterministic code decides required / recommended / optional from the kit and the video category (no model).

**C6 (only if time allows and C1-C5 are green) Question module:** typed questions (upload, choice, short text, Skip); ask only what is missing; replaces the free-text questions list in `IntakeOut`; `intakeNode` in `packages/director/src/nodes.ts`. If you stop before C6, say so.

Report format asked for: status per step, test counts, commit hashes, what is unproven.
